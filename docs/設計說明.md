# Air Jam（空中即興）：設計說明

> **Air Jam** 是一個給大家玩的手勢音樂遊戲：讓不會演奏樂器的人，也能跟著自己喜歡的歌享受即興演出的快樂。遊戲會聽歌、找出現在的和弦，玩家怎麼彈都和諧。
>
> Air Jam 會有多種「空中樂器」。**第一個樂器是「空中弦」**（這份文件第 3～11 節）：用雙手在空中拉出會留下來的弦，用手指撥弦。之後會加入其他樂器（見第 16 節）。
>
> 定位：先做成給一般玩家的完整遊戲，品質以真正玩家的體驗為準；之後再從完整專案拆出簡化版本給學生學習。

## 0. 架構：讓之後能加樂器

- 「聽懂歌曲」（解碼、拍點、和弦、調性）、「手部追蹤與手勢」、「和弦吸附」、「節奏判定與計分」、「畫面特效」做成**共用模組**，不綁在某一個樂器上。
- 每個樂器是一個獨立模組，提供一致的介面，例如：`init(ctx)`、`onHands(hands, time)`（收到手部資料）、`update(dt)`、`draw(ctx2d)`、`onChordChange(chord)`、`dispose()`。樂器透過共用的音高吸附、發聲與計分服務工作。
- 音色（木吉他、電吉他……）和樂器（空中弦、空中鼓……）分開：同一個樂器可以換音色。
- 程式可讀、模組清楚即可，不需要寫給初學者看的註解；註解用繁體中文或英文都可以，保持一致。

## 1. 目標與靈感

- **目標玩家：** 不會演奏任何樂器、但喜歡音樂的一般人。也要讓會樂器的人覺得好玩（`free` 模式、獨奏模式）。
- **核心體驗：** 放一首自己喜歡的歌 → 在空中拉幾條弦 → 跟著節奏撥 → 聽起來就像自己在幫這首歌伴奏。
- **兩個模式的目標（[D-012](決定紀錄.md)）：**和弦（伴奏）版要能隨興地刷出好聽的和弦；獨奏版要能用幾種簡單的動作做出帥氣的吉他 solo。要能配搖滾演奏曲（擁有者的範例歌見 CLAUDE.md）。
- **靈感來源（要標註）：**
  - 一支 Facebook Reel：雙手捏出停在空中的弦，弦的長度決定音高，靈感來自 Pat Metheny 的 42 弦「畢卡索吉他」。
  - Casio CT-FS1 電子琴的 Feel Sync：分析歌曲的和弦進行，即時修正玩家彈的音高，讓人「彈不出錯音」。
- **我們自己加的部分：** 把 Feel Sync 的「和弦吸附」套在空中弦上、撥弦速度控制音量、撥弦位置控制音色、節奏判定與連擊。

## 2. 技術限制

- **純前端**，不加後端；音樂檔只在玩家自己的瀏覽器裡分析，**不上傳**。
- 手部追蹤：MediaPipe Tasks Vision `@mediapipe/tasks-vision@0.10.14`，從 jsDelivr CDN 載入，`numHands: 2`，`runningMode: 'VIDEO'`。
- 聲音：瀏覽器內建 **Web Audio API**，不用其他函式庫。
- 原生 ES module、不需要建置步驟，用本機伺服器開啟（`python -m http.server`），已經發布在 GitHub Pages（從 `main` 的根目錄直接發布）。檔案結構依第 0 節的模組劃分（例如 `src/core/`、`src/instruments/`），自行決定。
- 把可調整的數值集中在設定物件（`SETTINGS`），之後可以接到遊戲內的設定選單。
- 畫面像照鏡子（影片左右翻轉），**手的座標也要用同一個翻轉**，弦、手、撥弦判定都在同一個座標系統裡。
- 介面文字先用繁體中文，但集中管理，之後方便加英文。
- 以 Chrome／Edge 桌機為主要目標；Safari、手機之後再支援，不要寫死只能在 Chrome 跑的東西。

## 3. 遊戲流程

1. **開始畫面：** 標題、一句說明、兩個按鈕：
   - 「選一首我的歌」（`<input type="file" accept="audio/*">`，MP3／WAV／M4A）
   - 「用內建示範曲」（程式自己合成的伴奏，見第 7 節）
   - 這一下點擊同時解鎖瀏覽器的聲音（瀏覽器規定要使用者先點一下才能出聲）並打開鏡頭。「選一首我的歌」要在**打開檔案視窗之前**就解鎖聲音：選檔案可能花很久，等到選好時那一下點擊已經「過期」了。之後每次按「開始演奏」「再玩一次」也會再呼叫一次 `resume()`。
   - 超過 `maxSongMinutes`（預設 15 分鐘）的檔案不分析，請玩家換一首（解碼後的音訊每分鐘約 23 MB）。
2. **分析歌曲：** 顯示「正在聽這首歌…」與進度條。把整首歌先分析一遍，得到 **拍點時間表** 和 **每一段的和弦**（見第 6 節）。
3. **暖身（實作時加的）：** 分析完先進入「先拉幾條弦試試看」，歌還沒開始，可以拉弦、撥弦聽聲音（不計分）。按「開始演奏」或空白鍵才開始播歌。這樣玩家不用一邊聽歌一邊摸索怎麼拉弦。
4. **遊戲中：**
   - 背景是鏡頭畫面（稍微調暗），上面畫手、弦、粒子。
   - 畫面上方顯示：歌曲進度條、**現在的和弦名稱**（例如 `Am`）、下一個和弦的預告、分數與連擊數。
   - 歌曲播放，玩家拉弦、撥弦。
5. **結束畫面：** 歌曲播完（或按 `Esc` 提早結束）後顯示分數、最高連擊、Perfect／Good 次數，按鈕「再玩一次」「換一首歌」。

## 4. 手勢

用 MediaPipe 的 21 個點。距離一律**除以手掌大小**（第 0 點手腕到第 9 點中指根部的距離），手離鏡頭遠近才不會影響判斷。

### 4.1 捏住（拉弦用）

- 拇指尖（4）與食指尖（8）的距離 / 手掌大小 < `pinchOn`（例如 0.35）→ 捏住。
- 要大於 `pinchOff`（例如 0.5）才算放開。兩個門檻不同（遲滯），避免手抖造成一直閃爍。
- 捏點位置 = 4 與 8 的中點。

### 4.2 拉出一條弦

1. 兩手**都**捏住 → 開始拉弦，兩個捏點之間畫出「預覽弦」（半透明、虛線），弦上畫刻度。
2. 拉的時候即時顯示這條弦**現在會發什麼音**（例如在弦旁邊寫 `Do`／音名），刻度畫在可以吸附的長度上，像吉他的琴格。
3. 兩手放開（任一手先放開也可以，給 150 ms 寬限）→ 弦固定在空中，變成實線，輕輕「叮」一聲當作確認。
4. 太短的弦（< 畫面寬度的 8%）不建立。
5. 弦數上限 `maxStrings`（預設 8）。超過時最舊的那條淡出消失。

### 4.3 撥弦

- 用**食指尖（8）**撥。正在捏（拉弦中）的手**不能**撥弦，避免拉新弦時誤撥舊弦。
- 判定方式：每一格記住指尖在每條弦的哪一側（外積的正負號）。上一格與這一格的**側邊改變**，而且指尖的移動線段真的和弦線段相交 → 撥到了。這比判斷「碰到」穩定，手抖也不會一直觸發。
- 同一條弦撥完後有冷卻 `pluckCooldown`（例如 120 ms）。
- **一次劃過好幾條弦＝刷和弦**：一格內撥到的多條弦，依照手指經過的順序間隔約 15 ms 依序發聲，聽起來像刷吉他。
- 撥弦時讀出兩個資訊：
  - **手指速度**（像素／秒，除以手掌大小）→ 音量。慢慢撥小聲，用力刷大聲。
  - **撥的位置**（在弦上的比例 0～1，中間是 0.5）→ 音色。靠近端點比較亮、比較尖；撥中間比較圓潤（真吉他也是這樣）。

### 4.4 其他手勢

- **刪除一條弦：** 單手握拳，拳頭中心停在某條弦上 0.8 秒 → 那條弦碎成粒子消失。
- **全部清空：** 雙手同時握拳 1 秒。
- （之後可以加）張開手掌往上推 → 調整音量。

握拳判定：四根手指的指尖（8、12、16、20）到手腕（0）的平均距離 / 手掌大小 < 門檻。

## 5. 音高：讓人彈不出錯音（核心）

### 5.1 長度決定「這條弦在第幾格」

真的弦越長越低，這裡保留這個直覺，但不直接把長度換成頻率，而是換成「格子」：

- 把弦長正規化：`t = (長度 - 最短) / (最長 - 最短)`，最短、最長約為畫面寬度的 8% 和 90%。
- 長的弦 → 低音，短的弦 → 高音。分成 `slots` 格（預設 10 格，橫跨大約兩個八度）。
- 每一格代表「**目前和弦的第 N 個和弦內音**」，由低往高排。例如和弦是 C（C E G），格子依序是 C3 E3 G3 C4 E4 G4 C5 …

### 5.2 和弦一換，弦就自動「重新調音」

- 每條弦存的是「第幾格」，不是固定的頻率。
- 歌曲換到 `Am`，同一條弦會自動變成 Am 的和弦內音（A C E）的對應位置。
- 這就是 Feel Sync 的做法：**按哪裡都對**，因為整組弦永遠只會發出現在這個和弦裡的音。
- 換和弦時，所有弦的顏色在 0.3 秒內漸變成新和弦的顏色，讓玩家「看到」和弦換了。
- 正在響的音不要突然換高，下一次撥才用新音高。

### 5.3 三種吸附模式（設定裡可以切換）

| 模式 | 說明 | 適合 |
|---|---|---|
| `chord`（預設） | 只會發出目前和弦的和弦內音 | 完全不會的人，怎麼撥都和諧 |
| `scale` | 吸附到歌曲調性的音階（大調或小調的 7 個音） | 想彈一點旋律的人 |
| `free` | 不吸附，長度直接換成頻率（頻率 ∝ 1／長度） | 想自己玩、會一點音樂的人 |

沒有分析結果時（例如分析失敗），自動退回 `scale` 模式並用 C 大調五聲音階（C D E G A），一樣不會有難聽的音。

## 6. 聽懂一首歌（在瀏覽器裡分析）

歌曲載入後**先完整分析一次**再開始播放（比邊播邊分析穩定，也能預告下一個和弦）。分析可以放在 `setTimeout` 分段做或用 Web Worker，不要讓畫面卡住；進度條要會動。

**實作：** 分析寫成 generator（`analyzeSteps`），在主執行緒上每 20 ms 切一段（`analyzeAsync`），Node 測試用同一份程式一次跑完（`analyzeSync`）。沒有用 Web Worker：一首 4 分鐘的歌約 2～3 秒，分段已經夠順；之後如果要支援手機再考慮。

### 6.1 解碼

`AudioContext.decodeAudioData` → 混成單聲道 → 降取樣到約 11025 Hz（夠分析和弦，也比較快）。

### 6.2 拍點（節奏）

1. 每一小段（11025 Hz、hop 256 樣本，約 23 ms）算頻譜，計算**頻譜流量**（spectral flux：這一段比上一段「變大」的能量總和），得到「起音強度」曲線；另外算一條 180 Hz 以下的（貝斯和大鼓）。
2. **先找脈動（tatum），再決定一拍是幾個脈動。** 拍點一定是整數個脈動，所以不會落在兩個音符中間。
   - **脈動**（`estimatePulse`）：對去掉平均的起音曲線做自相關。每個候選週期的分數是「它所有倍數位置的自相關平均」（4 秒內）。先取分數最高的週期（常常是一拍或兩拍），再試著切成 2 份或 3 份：新切出來的位置的自相關要有原本位置的 30% 以上，才算真的有脈動，可以一直切下去（最短 110 ms）。切錯比例（例如 1.5 個脈動）會讓一半的新位置落在音符中間，所以通不過。最後用 12 秒內的倍數微調週期。
   - **一拍幾個脈動**（`chooseGrouping`）：在追蹤到的脈動上取起音強度，看它在 2、4、8 個脈動的自相關（二拍子）和 3、9 個脈動（三拍子）；三拍子要明顯比較強（差 0.1 以上）才選。二拍子的候選是 1、2、4 個脈動，三拍子是 1、3 個，只留 70～180 BPM 內的。候選之間用「拍點與它倍數的起音自相關 × 偏好 110 BPM 的先驗」挑一個，再做八度檢查：快一倍的候選，起音和低音頻段在那個間隔都要夠強（≥ 25%、≥ 30%）才換過去（大鼓、貝斯很少比一拍還密）。
3. 用動態規劃（Ellis 2007）沿著起音排出整首歌的拍點時間表（允許速度慢慢飄），再用鄰近拍點的線性回歸去掉量化誤差；安靜的前奏和尾奏用同樣的間隔補滿。
4. 每 4 拍當作一小節（第一拍畫得比較明顯）；小節的起點選「和弦變化最大」的相位。三拍子分組時一小節是 4 個附點拍（12/8 的感覺），沒有做 3/4。

**為什麼要分兩步（實作時發現的）：** 搖滾常見每分鐘 200～320 下的八分音符脈動，「兩個一組」和「三個一組」都落在 70～180 BPM 裡。舊版直接在這個範圍找最強的拍子週期，加上偏好 110 的先驗，在擁有者的兩首範例上都選錯：`sample 21` 的脈動是 285.7 ms，舊版的一拍 428 ms＝1.5 個脈動（140 BPM，每隔一拍落在兩個音中間），新版是 2 個脈動＝104.9 BPM；`sample 14` 的脈動是 187.5 ms，舊版一拍＝3 個脈動（107 BPM），新版 2 個脈動＝160 BPM（也可能是 80，要擁有者用耳朵確認）。合成測試裡的「搖滾八分音符」歌（105、160 BPM）舊版也是錯成 70 和 107。數字見 `node tests/samples.test.mjs` 和 [搖滾獨奏_設計挑戰.md](搖滾獨奏_設計挑戰.md) 開頭的狀態。

#### 6.2.1 手動修正速度

自動分析還是可能差兩倍或 1.5 倍，所以設定面板（11.1）有一組按鈕，暖身和演奏中都能用，也能用按鍵：

| 按鈕 | 鍵 | 作用 |
|---|---|---|
| 慢一半／快一倍 | `[` `]` | 一拍的長度 ×2／÷2 |
| ÷1.5／×1.5 | `;` `'` | 一拍＝3 個脈動 ↔ 2 個脈動（例如 107 ↔ 160）；連按可以組出 ×3/4、×4/3 |
| 拍點提早／延後 | `,` `.` | 整個拍點表移一個脈動（一拍只有一個脈動時移半拍） |
| 還原 | `0` | 回到自動分析的結果 |
| 節拍器 | `K` | 演奏時在每一拍發出滴答聲（小節第一拍比較高），用耳朵確認拍子 |

修正不用重新解碼或重算頻譜：分析結果保留起音曲線和每一小段的色度（`features`，不會被列舉），`retime(analysis, { factor, shift })` 是純函式，用新的拍長重跑動態規劃，再重算小節、每拍和弦和段落，換成新的歌曲地圖。倍率是相對於自動結果的，所以「還原」一定回到原本；速度限制在 40～320 BPM。演奏中修改時，計分從目前這一拍重新算起。

### 6.3 和弦

1. 用 FFT（自己寫一個小的 radix-2 FFT 就好，不用函式庫）算每一段的頻譜，把 55 Hz～2000 Hz 的能量依音名（C、C#、…、B）加總成 **12 維的色度向量（chroma）**，再正規化。
2. 以**每一拍**為單位，把那一拍內的 chroma 平均。
3. 和 **24 個和弦模板**（12 個大三和弦＋12 個小三和弦，例如 C = C、E、G 三個位置為 1）做相似度比對，取最高分。
4. 平滑化：和弦通常至少持續 2 拍。用簡單的方法（例如 Viterbi，換和弦有懲罰；或「連續兩拍都一樣才換」）去掉亂跳。
5. 用整首歌的 chroma 總和，和大調／小調輪廓（Krumhansl 調性輪廓）比對，估出**調性**，給 `scale` 模式用。

**實作補充：**

- 色度只取頻譜峰值（拋物線內插）。一個很大聲的單音（人聲、主旋律）的第 3、第 5 泛音剛好是它的五度和大三度，會讓單音看起來像大三和弦，所以當一個峰值的 1/3 或 1/5 頻率上有一樣大或更大的峰值時，它的權重打三折（`overtoneSuppression`）。
- 小節的第一拍：找「和弦變化最大」的相位。Viterbi 換和弦的懲罰在第一拍最小、第 2、4 拍最大。
- 拍點：先找脈動、再決定一拍是幾個脈動，見 6.2（2026-11-25 改寫；舊版「直接找週期、偏好 110 BPM」的做法在搖滾上會選錯）。排拍點仍用 Ellis 動態規劃加區域線性回歸，前後安靜的地方用相同間隔補上拍點。

| 測試歌 | BPM | 每拍和弦正確率 |
|---|---|---|
| 8 首簡單合成伴奏（三和弦、各種速度、有無鼓、旋律、雜訊） | 全對 | 91～100% |
| 撥弦吉他樂團：三和弦、搖擺、速度 96→101、前奏只有鼓、小聲人聲 | 對 | 94% |
| 同上，但是七和弦＋轉位 | 對 | 44% |
| 同上，人聲很大聲 | 對 | 16% |
| 慢歌 70 BPM：分解和弦、轉位和弦、沒有鼓、人聲很大聲 | 猜成兩倍（138） | 39% |
| 搖滾八分音符：12 小節藍調 105 BPM＋人聲 | 對 | 77% |
| 搖滾八分音符：12 小節藍調 140 BPM＋人聲 | 對 | 52% |
| 搖滾八分音符：Am–G–F 160 BPM | 對 | 63% |
| 搖滾八分音符：Am–G–F 80 BPM | 猜成兩倍（160，測試接受） | 63% |

結論：拍點在所有測試裡平均誤差都在 7 ms 以內；和弦在「伴奏清楚的三和弦流行歌」上可靠，**七和弦和大聲的人聲是主要弱點**。之後可以試的方向：用立體聲的左右差（人聲通常在正中間）、NNLS 色度、加入七和弦模板再對應回三和弦。這些都要用真的歌測過再決定。

分析的準確度不需要完美：就算和弦猜錯，`chord` 模式發出的仍然是三和弦的音，頂多「有點怪」，不會刺耳。**在結束畫面或說明裡誠實寫出：「和弦是程式猜的，不一定每個都對。」**

### 6.4 播放

用 `AudioBufferSourceNode` 播放解碼好的歌，以 `audioContext.currentTime` 為準來對照拍點與和弦時間表（不要用 `Date.now()`，才會跟聲音同步）。音量設定：歌曲 `songVolume`、撥弦 `stringVolume`，分開可調。

## 7. 內建示範曲

讓沒有音樂檔、或想先測試的人也能玩，而且**拿來驗證分析程式對不對**：

- 程式自己合成一段約 40 秒的伴奏：100 BPM，和弦進行 `C – G – Am – F` 重複，每個和弦 1 小節（4 拍）。
- 樂器：低音（和弦根音）、鋪底和弦（柔和的三角波）、簡單的鼓（大鼓在 1、3 拍，小鼓用雜訊在 2、4 拍）。
- **實作：** 改用純 JavaScript 合成（`src/core/song/backing-synth.js`），不用 `OfflineAudioContext`，這樣 Node 測試和瀏覽器分析的是同一個訊號。
- 合成出來的聲音 **走跟玩家音樂檔一模一樣的分析流程**，不要偷用已知答案。分析結果應該要接近 100 BPM 和 `C G Am F`；開發者可以在 console 印出比對結果。

## 8. 撥弦的聲音

使用 **Karplus-Strong 撥弦合成**：一小段隨機雜訊，放進「延遲線＋低通平均」的迴圈裡，會自然變成很像吉他的撥弦聲。

- 每次撥弦預先算好一個短的 `AudioBuffer`（約 2 秒）再播放，最簡單也最穩定（不用 AudioWorklet）。
- 頻率決定延遲線長度；`decay` 決定餘音長短。**實作：** 餘音用「衰減 60 dB 的秒數」計算，音越高餘音越短（像真的弦）；`decay` 當作整體倍率，0.996 是標準長度，越接近 1 越長。延遲線加一個全通濾波器補小數部分，音準誤差在 1 cent 以內。
- 同一條弦再撥一次時，上一個還在響的聲音會很快淡出（像真的弦被手指碰到），不會疊在一起。
- **撥的位置** → 初始雜訊先做一點低通（撥中間＝低通多一點，聲音圓潤；撥端點＝幾乎不過濾，聲音亮）。
- **速度** → 音量（GainNode），設上下限。
- 加一點點立體聲左右（StereoPanner）：弦的中點在畫面左邊就偏左聲道。
- 同時發聲的數量上限（`maxVoices`，16 個），太多就把最舊的淡出，避免爆音。撥弦先經過一個輕的壓縮器，再和歌曲一起進最後的限制器（`DynamicsCompressorNode`）防止破音。限制器會自動補增益、起音也會漏過一點，所以最後還有一個固定的輸出上限（0.9 以下不動，最高 0.99；見 15.1.1 的量測）。電吉他的長音只先算前 0.4 秒，其餘在之後的空檔裡算（15.1.3）。

## 9. 遊戲性：節奏判定

不會彈的人也需要「我有沒有彈好」的回饋，但**不能有懲罰感**。

- 撥弦時間和最近的拍點比較：
  - 差距 ≤ 70 ms → **Perfect**（大的金色字＋較多粒子）
  - 差距 ≤ 150 ms → **Good**
  - 其他 → 照樣發聲、照樣好聽，只是不加分（不顯示 Miss，不扣分）
- 連續 Perfect／Good → 連擊數增加，連擊越高，弦的光暈越亮、粒子越多。
- **實作：** 不在拍子上的撥弦**不會**中斷連擊（不然隨意撥弦會有懲罰感）；連續 `comboIdleBeats`（8）拍都沒有得分，連擊才悄悄歸零。每一拍只算一次分，在同一拍附近亂撥不會一直加分。
- **延遲補償：** 判定時間 = 歌曲時間 − 喇叭輸出延遲（`outputLatency`）− 輸入延遲（鏡頭 `cameraLatency` 60 ms、滑鼠 `mouseLatency` 12 ms），以玩家「聽到」的拍子為準。
- 顯示和吸附用的和弦比聽到的聲音早 `chordLookahead`（40 ms）切換，剛好在換和弦那一拍撥下去，也會發出新和弦的音。
- 在**小節第一拍**撥到，而且那一拍剛好換和弦 → 額外加分（「跟上換和弦了！」）。
- 畫面邊緣有隨拍點閃動的提示光（第一拍比較亮），讓玩家看得到節奏。
- 刷和弦（一次撥到 3 條以上）且在拍點上 → 分數加倍。`strumWindow`（140 ms）內的撥弦算同一次刷弦，只判定一次。

## 10. 視覺

- **弦：** 發光的線（畫兩次：粗而半透明的光暈＋細而亮的芯）。顏色依目前和弦決定（12 個根音對應色相環的 12 個顏色，小和弦稍微暗一點）。
- **刻度：** 弦上畫小刻度，表示吸附的格子；拉弦時更明顯，固定後變淡。
- **震動：** 撥弦後，弦畫成會衰減的駐波：在撥的位置彎最多，`振幅 × sin(…)`，振幅隨時間指數變小，和聲音的餘音同步。
- **粒子：** 撥的位置噴出粒子，顏色跟弦一樣。Perfect 時更多。
- **手：** 畫 21 個點和連線，但淡一點；捏住時捏點畫成亮圈，食指尖畫成小光點，方便瞄準。
- 鏡頭畫面調暗約 40%，讓弦和粒子更明顯。

## 11. 沒有鏡頭也能測（滑鼠模式）

- **不按鍵移動滑鼠穿過弦**＝撥弦（速度一樣換算音量）。
- 右鍵點弦＝刪除那條弦。

## 12. 設定（`SETTINGS`）

```js
const SETTINGS = {
  snapMode: 'chord',     // 'chord' 和弦內音／'scale' 音階／'free' 不吸附
  slots: 10,             // 弦長分成幾格（越多，音域越廣）
  lowestNote: 'C3',      // 最長的弦大約從哪個音開始
  maxStrings: 8,         // 最多幾條弦
  pinchOn: 0.35,         // 捏住的門檻（越小越要捏緊）
  pinchOff: 0.5,         // 放開的門檻
  pluckCooldown: 120,    // 同一條弦多久才能再撥一次（毫秒）
  songVolume: 0.8,       // 歌曲音量
  stringVolume: 0.9,     // 撥弦音量
  decay: 0.996,          // 撥弦餘音（越接近 1 越長）
  perfectWindow: 70,     // Perfect 判定範圍（毫秒）
  goodWindow: 150,       // Good 判定範圍（毫秒）
  showHand: true,        // 要不要畫出手的 21 個點
  videoDim: 0.4,         // 鏡頭畫面調暗多少
};
```

實作時另外加的設定（`src/settings.js`）：`tone`、`maxVoices`、`minStringLength`／`maxStringLength`、`releaseGrace`、`newStringGuard`（新弦 250 ms 內不能撥）、`crossDeadband`（穿越判定的緩衝帶）、`strumGap`、`strumWindow`、`velocityFull`、握拳的 `fistOn`／`fistOff`／`fistReach`／`fistDeleteTime`／`fistClearTime`、`cameraLatency`、`mouseLatency`、`chordLookahead`、`comboIdleBeats`、`maxSongMinutes`；`metronome`（節拍器，`K` 鍵切換，用來用耳朵確認速度）；電吉他的強力和弦用 `powerLowestNote`（`E2`）、`powerSteps`（5）和 `keyGuard`（調內根音保護，預設開，設定面板的「進階」可以關，見 15.1.1）；`pedals`（顯示腳踏區，預設開）。玩家用按鈕改過的值記在 `localStorage`，見 11.1。

## 13. 會遇到的問題

| 問題 | 原因 | 解法 |
|---|---|---|
| 按了沒聲音 | 瀏覽器規定使用者要先點一下才能播放聲音 | 開始按鈕的那一下同時 `audioContext.resume()`；選檔案要在打開檔案視窗前就解鎖 |
| 切到滑鼠模式後鏡頭燈還亮著 | 鏡頭或模型還在載入時就切換了 | 載入完成時檢查是否已經切換，是的話關掉鏡頭 |
| 手指明明碰到弦卻撥不到 | 影片翻轉了，手的座標沒翻 | 所有座標用同一套翻轉 |
| 拉新弦時舊弦一直響 | 捏住的手也被當成在撥弦 | 捏住的手不能撥 |
| 捏住判斷一直閃 | 手會抖，一個門檻不夠 | 捏住和放開用兩個不同門檻 |
| 一次撥好幾聲 | 指尖在弦附近抖 | 用「穿過」判斷＋冷卻時間 |
| 聲音和畫面對不上 | 用了 `Date.now()` 計時 | 改用 `audioContext.currentTime` |
| 很多弦一起響會爆音 | 音量加總太大 | 同時發聲上限＋壓縮器 |
| 分析一首歌時畫面卡住 | 一次算完整首歌 | 分段計算或用 Web Worker，顯示進度 |
| 和弦有時候猜錯 | 自動分析本來就不完美（人聲、鼓聲會干擾） | 平滑化，並誠實告訴玩家 |

### 15.1 音色

> **狀態：木吉他（鋼弦）、古典吉他（尼龍弦）和電吉他已實作（`src/core/audio/tones.js`，`T` 鍵切換）。電吉他是音色實驗室的丁，加上效果器板的過載和破音（15.1.3）和娃娃音（15.1.4）；有破音時彈強力和弦（15.1.1）。其餘是草案**（2026-11-25）。搖滾獨奏的音色另見 [搖滾獨奏_設計挑戰.md](搖滾獨奏_設計挑戰.md)，還沒有決定。

同一個撥弦演算法（Karplus-Strong）加上不同的參數與效果鏈：

| 音色 | 做法 |
|---|---|
| 木吉他（鋼弦） | 預設；餘音長、明亮，加一點殘響（已實作） |
| 古典吉他（尼龍弦） | 較暗、較圓，起音柔和（已實作） |
| 電吉他乾淨音 | 電吉他把過載和破音都關掉（效果器板的「清音」，15.1.3）；可以再加合聲（15.1.7） |
| **電吉他破音** | `WaveShaperNode` 削波 → **音箱模擬**（低通約 4–5 kHz＋EQ，或 `ConvolverNode` 套音箱脈衝響應；沒有這層會又刺又沙）（已實作：丁＋過載、破音兩顆效果器，用濾波器做音箱，見 15.1.3） |
| 烏克麗麗、豎琴 | 調整音域、餘音與亮度 |

效果器：Distortion／Overdrive、**娃娃音（Wah）**（帶通濾波移動中心頻率約 400 Hz ↔ 2 kHz）、Chorus／Flanger（調變短延遲）、Delay（延遲＋回授）、Reverb（卷積殘響）、推弦／搖桿（改變播放速率）。

兩個 Air Jam 才有的玩法：
- **用手控制娃娃音：** 沒在撥弦的那隻手的高度控制 Wah 濾波頻率，取代真吉他的腳踏板。（已實作：手要伸進畫面邊緣的直條，另有自動模式，見 15.1.2、15.1.4）
- **破音時改用強力和弦：** 三和弦加重破音會糊掉，所以有開過載或破音時，「和弦吸附」自動改成只用根音＋五度；兩顆都關（清音）就回到三和弦。（已實作，見 15.1.1、15.1.3）

#### 15.1.1 電吉他破音與搖滾和弦模式（已實作，2026-11-25）

> 下面「效果鏈」和「混音與音量」講的是改成丁之前的電吉他（現在是音色實驗室的甲，`LEGACY_ELECTRIC`）。現在的電吉他見 15.1.3；強力和弦、換和弦收音、調內根音保護的規則沒有變，只是「電吉他音色時」改成「電吉他有開過載或破音時」。

目標（[D-012](決定紀錄.md)）：配搖滾演奏曲隨便刷，也是好聽的和弦。做法來自 [搖滾獨奏_設計挑戰.md](搖滾獨奏_設計挑戰.md) 4.1 的和弦模式（第 1 階段），獨奏的部分還沒做。

**效果鏈**（`src/core/audio/tones.js` 的 `electric`，數值在 `RHYTHM_DISTORTION`）：撥弦（Karplus，`t60` 1.3 秒、比較亮）→ 高通 110 Hz（破音前先收緊低音）→ 750 Hz 中頻推一點 → 前級增益 → `WaveShaperNode` 軟削波（tanh，稍微不對稱，4 倍超取樣）→ 音箱模擬：高通 75 Hz、120 Hz 小鼓起、420 Hz 挖 4 dB（去混濁）、1.7 kHz 加 3 dB（中頻往前）、兩段低通約 4.5 kHz（陡的高頻衰減，破音才不會刺）。不用音箱脈衝響應檔，也不加殘響（乾、短，換和弦收音才收得乾淨）。破音的小訊號增益約 24 dB。

**聲部（part）：**引擎裡每個聲部有自己的發聲匯流排、音色和效果鏈（現在只有 `rhythm`），換音色只換那個聲部的鏈。之後的主奏聲部會有自己的削波器，不會和強力和弦一起進同一個破音而糊在一起（挑戰文件 M5）。

**強力和弦發聲：**`chord` 模式、電吉他音色時，每條弦只發根音或五度。最長的弦是根音，放在 E2～D#3 之間（像吉他最低的兩條弦），往上依序是五度、八度、八度上的五度、再高八度，一共 5 個音、兩個八度（`powerSteps`）。弦長一樣分成 10 格，所以相鄰兩格可能是同一個音，就像真的刷強力和弦時好幾條弦彈同一個音；比木吉他（從 C3 往上三個八度多）低而且窄。介面上的和弦寫成 `A5`（＝A 的強力和弦：只有 A 和 E，沒有三度，所以不分大小調）。`scale`、`free` 模式不變。

**換和弦時收掉舊的音：**和弦一換，還在響、而且不屬於新和弦的音在 80 ms 內淡出（`chordChoke`）；新和弦也有的音（例如 A5 換 E5 時的 E）繼續響。破音會把衰減壓平：輸入小 24 dB，輸出幾乎不變，所以淡出的深度要加上破音的增益（`releaseDepthDb` 90 dB，木吉他維持原本的 26 dB）。同一條弦重撥、超過發聲上限時的淡出，也用同樣的深度，並從新的音開始的那一刻算起。

**和弦從哪來：**保留三和弦追蹤（含平滑），只取它的根音（`src/core/music/power-chords.js`）。Am 和 A 都變成 A5，前後相同就合併成一段。

**調內根音保護（`keyGuard`，預設開；要不要能關、預設開或關，還等擁有者決定）：**根音只能是調性主音的這些級數（以半音算）：

| 調性 | 允許的根音 | A 調的例子 |
|---|---|---|
| 小調 | I、♭III、IV、V、♭VI、♭VII | A 小調：A、C、D、E、F、G |
| 大調 | 同上，再加 ii、vi | A 大調：A、B、C、D、E、F、F#、G |

不在裡面的根音，換成**前一個**調內的根音（猜錯的和弦通常是同一個和聲多了一個音，例如 A6 被聽成 F#m）；歌一開始就不在調內，用後面第一個調內的根音；整首都不在，用主音。

規則的考量：搖滾常借用 ♭III、♭VI、♭VII，所以大小調都允許；大調另外允許 ii、vi，因為流行搖滾、龐克最常見的 I–V–vi–IV 就有 vi。藍調搖滾（大三度、小七度都有，例如 s21）在這個規則下也算大調；如果藍調不允許 vi、ii，s21 會比較乾淨（見下面），但大調流行歌的 vi 會被換掉。iii 被排除（大調歌的 iii 會被換成前一個和弦）。調性本身猜成關係大小調時（例如 A 小調猜成 C 大調），E（V）會被當成 iii 換掉，這是已知的風險。

**在範例歌上的效果**（`node tests/samples.test.mjs`）：s14（A 小調）的根音全部在調內，23 段三和弦變成 23 段強力和弦（A5、G5、F5、E5），保護沒有換掉任何一拍。s21（A 大調）的 18 段也全部在調內（G、F、A、F#、E、D），保護沒有換掉任何一拍，強力和弦是 `G5 F5 A5 F#5 A5 E5 F#5 A5 G5 A5 D5 A5 G5 F#5 A5 G5 A5 F#5`。也就是說，**s21 的標籤亂不是調外根音造成的**：F#、E、G 都是合理的根音，只是很可能是 boogie 音型（A5–A6–A7）裡的 F#、G 被聽成和弦。拿掉三度之後，F#5（F#＋C#）疊在 A 的 boogie 上是 A6 的音、E5 是五度和九度、G5 是七度和四度，都不太衝突；比較可能刺耳的只有開頭 1.7～4.0 秒的 F5。如果「大調也不允許 ii、vi」，s21 會變成 13 段（F#5 全部換成前一個和弦），s14 不變。瀏覽器解碼 MP3 的分析結果和 Node 讀 WAV 的不完全一樣（s21 從 Am 開始，18 段三和弦 → 17 段強力和弦），但一樣沒有被換掉的拍。

**合成測試歌**（`node tests/analysis.test.mjs`，表格的 roots 欄）：16 首都沒有退步（保護後的根音正確率 ≥ 保護前），也沒有留下調外的根音。被換掉的拍：大聲人聲的流行歌 4 拍、70 BPM 慢歌 32 拍、Am–G–F 160 BPM 12 拍，正確率都沒變。

**混音與音量**（瀏覽器 `OfflineAudioContext` 跑真的音訊圖：8 條弦、力道全滿、每個八分音符刷一次、每小節換和弦，疊在範例歌 10～26 秒上）：電吉他單獨的 RMS 約 −12.5 dB（s21）／−12.1 dB（s14），歌曲單獨 −14.0／−12.7 dB，所以大約和歌一樣大、稍微浮在上面；力道一半時約 −14 dB。左右差（side）只有 −25 dB，幾乎在正中間（歌曲是 −8 dB，很寬）。總輸出的峰值 0.97（兩首都是）。原本的限制器（`DynamicsCompressorNode`）會自動補增益、也會讓起音漏過去，同樣的刷法用木吉他也會到 1.01～1.02，所以最後加了一個固定的輸出上限（`ceilingCurve`：0.9 以下不動，最高 0.99）。換和弦收音在真的音訊圖上量：撥完 0.4 秒後換和弦，約 51 ms 降到 −40 dB、80 ms 時 −79 dB；不收音的話 80 ms 後只小 6 dB。

**還沒驗證：**沒有人聽過（自動測試只能量數字）；破音的音色、強力和弦會不會被歌裡的吉他牆蓋住、換和弦的收音聽起來會不會太突然，都要擁有者用兩首範例歌刷刷看。


#### 15.1.2 效果器板的介面與手勢（已實作，預設顯示；過載和破音的聲音見 15.1.3，娃娃音見 15.1.4，延音見 15.1.5，2026-11-25）

依擁有者 2026-11-25 的決定（畫面用現有 2D canvas、聲音和畫面完全分開；捏住上下拖轉旋鈕；捏一下開關；畫面下方的腳踏區；簡單／進階兩種模式；娃娃音用邊緣直條＋自動）做的介面和手勢。程式在 `src/core/pedals/`。原本要在網址加 `?pedals=1` 才出現；擁有者說看不到、不要用網址切換之後，**腳踏區預設顯示**，玩家可以在設定面板關掉「顯示腳踏區」（會記住；`?pedals=0`／`1` 留作開發用）。關掉時效果器板收不到手、不畫、快捷鍵也不作用。

**哪幾顆可以用（`availability.js`）：**介面層的旗標，和資料、聲音分開。還沒有聲音的效果器（目前：延遲、空間）畫成變暗、關著的樣子，加上「即將推出」的標籤；捏一下、點一下、`4`～`9` 都只會提示「即將推出（還沒有聲音）」，旋鈕也轉不動（娃娃音不能用時，`W` 也一樣，直條不出現）。存好的設定（例如預設組把空間打開）保留不動。目前可以用的是娃娃音、過載、破音和合聲（15.1.7）；某一顆的聲音接上後，把 `PEDAL_AVAILABLE` 裡那一項改成 `true`（或呼叫 `setPedalAvailability({ chorus: true })`）就好。

**資料（`model.js`，純資料）：** 六顆效果器：過載、破音、娃娃音、合聲、延遲、空間，音箱一直開著。每顆有開關和旋鈕（值存成 0～1，`knobValue()` 換成 dB／Hz／ms／% 給聲音端；有段數的旋鈕像延遲時間「短／附點／長」會吸附到段）。四個預設組「清音／微破／搖滾／重金屬」的數值見 15.1.3（搖滾＝丁）。**簡單模式**：預設組＋兩個總旋鈕（破音程度、明亮度，一次移動幾顆效果器的同一種旋鈕，保持它們之間的差距）＋每顆最多兩顆旋鈕，音量自動配平，效果鏈固定用標準順序。**進階模式**：每顆的全部旋鈕（含音量），可以用 ◀ ▶ 改效果鏈順序（音箱也在鏈裡）。改了任何東西，預設組就變成「自訂」。整份設定存在 `localStorage`（讀寫失敗不會出錯，壞掉的資料會變回預設）；拖旋鈕時不寫入，放開才存。

**聲音端的接口（`audio-binding.js`）：** 聲音端訂閱 `model.subscribe((snapshot, change) => …)`。`snapshot` 有 `mode`、`autoLevel`、實際使用的 `order`、每顆的 `on`、`sound`（有沒有 DSP）、`params`（0～1）和 `values`（實際單位）；`change` 說明這次改了什麼（toggle／param／order／preset／mode／load），拖動中的旋鈕 `commit` 是 false。`bindPedalAudio` 把每次改變交給引擎的 `applyPedals(snapshot, change)`；引擎是第一次點擊才建立的，所以遊戲在建立引擎時也會先送一次目前的設定。效果鏈的順序（進階模式的 ◀ ▶）**還沒有影響聲音**：固定是娃娃音 → 過載 → 破音 → 音箱。娃娃音的踏板位置不經過這個接口的鏈更新，引擎另外動它的位置訊號（15.1.4）。調整畫面的試聽循環用 `pedalboard.setAudition({ start, stop })` 接上；現在是空的。

**手勢（`gestures.js`，純函式，數值在 `SETTINGS`）：**

| 手勢 | 判定 | 設定 |
|---|---|---|
| 捏一下 | 從開著的手開始捏，0.4 秒內放開，捏點移動小於 0.5 個手掌 | `pedalTapTime` 400 ms、`pedalTapMove` 0.5 |
| 捏住不放 | 超過 0.4 秒或移動太多：什麼都不做（可以反悔） | — |
| 捏住上下拖（旋鈕） | 從捏住的位置算相對移動，超過 0.12 個手掌才開始轉，2.5 個手掌＝整個範圍；放開時用 100 ms 前的值（拇指和食指分開時捏點會跳）；手中途消失就保留那個值 | `pedalDragDeadband`、`pedalKnobTravel`、`pedalLatch` |
| 防連按 | 捏一下生效後 0.4 秒內，其他的捏一下都不算 | `pedalLockout` 400 ms |
| 剛出現的手 | 一出現就是捏著的（例如從畫面下緣伸進來）不算，要先張開；出現不到 150 ms 的手捏了也不算 | `pedalSettle` 150 ms |

**誰收到手（`pedalboard.js`）：** 每一格先給效果器板，再把剩下的手給樂器。手在腳踏區裡（指尖或捏點低於腳踏區上緣；離開要高出 0.25 個手掌，避免邊緣閃爍）、在娃娃音直條上、或正捏著一個從效果器板開始的動作，就**不給樂器**：所以在腳踏區裡不能拉弦、撥弦、握拳刪弦，雙手握拳清空也要兩隻手都在外面；從腳踏區開始的拖曳不會變成一條弦。手回到樂器時被當成新的手，不會因為舊位置誤撥。滑鼠右鍵刪弦在腳踏區裡也無效。

**畫面（`layout.js` 幾何、`draw.js` 畫圖；之後可以換成 3D，只換這兩個）：**

- **腳踏區**：畫面下方 20%（`pedalZoneHeight`），六顆依效果鏈順序排成一列，每顆是一個發光圓盤（一類一個顏色和圖示，沒有廠牌、型號或仿某台效果器的外殼）＋狀態燈＋右邊最多兩顆小旋鈕（值的弧線、指針）。手進來整區變亮；捏著時開關外面有亮圈，超過 0.4 秒變灰色虛線（放開不會切換）；切換後有 0.4 秒的倒數圈。準備畫面的面板和下方說明會往上移，不被擋住。

#### 15.1.3 電吉他＝丁＋過載、破音的聲音（已實作，2026-11-25）

擁有者在音色實驗室聽過甲乙丙丁：丁「可以做出像真的電吉他＋效果器的聲音」，乙、丙聽起來像沒什麼效果的電吉他；希望丁可以**更破碎**，而且有**旋鈕可以自己微調**。所以遊戲的電吉他改成丁，並把效果器板的過載和破音接上真的聲音。木吉他、古典吉他不變；實驗室的甲乙丙丁留著比較（甲＝改之前的電吉他）。程式在 `src/core/audio/electric-rig.js`。

**效果鏈**（每個聲音兩軌：雙軌的第二軌破音少 10%、中頻凸起高 100 Hz，和丁一樣）：

```
撥弦 → [娃娃音：旁通｜帶通＋補償（15.1.4）] → [過載：旁通｜推升級] → 高通 80 Hz、750 Hz +5 dB → [破音：乾淨｜硬削波｜粗糙削波] → 音箱 → 音量
```

- **過載**＝丁的推升級：700 Hz 以下壓 12 dB → 增益 → 軟削波（tanh）→ 低頻補回 6 dB → 低通 3.2 kHz → 音色（2 kHz 高架）。

- **音箱**一直開著（丁的值）：高通 75 Hz、150 Hz +6 dB、420 Hz 0 dB、1.7 kHz +3 dB、明暗傾斜（300 Hz／1.5 kHz 兩個架式，±6 dB）、兩段低通 4.5／5.6 kHz、250 Hz 低頻補回（破音開 +10 dB、只有過載 +9 dB、清音 +8 dB）、音量。
- 削波曲線永遠不換（換曲線會喀一聲），「破音量」是曲線前面的增益。

**改設定不會有雜音、不會重建：**電吉他的效果鏈每一軌建兩份，接同一個輸入，一次只聽得到一份。轉旋鈕時，聽得到的那份用 `setTargetAtTime`（時間常數 25 ms）慢慢滑過去；開關效果器、換預設組、換模式時，先把聽不到的那份直接設成新的值，5 ms 後兩份交叉淡入淡出（時間常數 12 ms，約 40 ms 換完），所以聽起來是兩個已經穩定的聲音之間的交叉淡化，不會有「大聲的分支還沒退、小聲的分支已經被補大」的爆音。正在淡化時又切換，就改成在聽得到的那份上滑過去。換和弦、刷弦的收音深度跟著目前的增益（`chokeDepthDb`），增益調大以後，之前撥的音也用新的深度收。代價：每一軌兩份、每份 3 個 4 倍超取樣的削波器，在音訊執行緒上大約是丁的兩倍。

**主執行緒的成本：**丁每個音兩軌、延音 6 秒，原本每個音都在主執行緒把整段 buffer 算完：一次 8 條弦約 22 ms（Chrome，這台電腦；Node 約 14～17 ms），在 30 fps 下就會卡一格。沒有用「快取算好的 buffer」：每次撥弦的雜訊都一樣會變成機關槍的聲音，而且 6 秒的 buffer 一個約 1 MB，一首歌的和弦就要上百 MB。改成**先算前 0.4 秒**，馬上播；剩下的放進佇列，在之後的空檔裡每次最多算 4 ms，接在前段的結尾（兩段都對齊到整數個取樣，所以接得剛好；測試確認分段算和一次算的每個取樣都一樣）。被新的一刷收掉的音，後段根本不算，所以一直刷的時候大部分的後段都省掉了。結果：一次 8 條弦約 2.1 ms（Chrome；最慢 2.4 ms），和改之前的甲（2.4 ms）差不多。量測用的 `OfflineAudioContext` 還是一次算完。

#### 15.1.4 娃娃音（已實作，2026-11-25）

依 D-016（畫面邊緣的直條＋自動模式）和擁有者 2026-11-25 的補充（左手控制、直條在左邊、要有慣用手設定；直條不能誤撥弦、滑鼠也能用；簡單模式控制少、好聽，進階模式像真的效果器）。程式：聲音 `src/core/audio/wah.js`、`stages.js`（`wahFilter`、`wahGain` 兩種段）、`electric-rig.js`、`engine.js`；介面 `src/core/pedals/`（15.1.2）。

**聲音：**接在過載和破音**前面**（真的效果器板的標準順序：娃娃音先挑出一段頻率，再進破音，破音會把那段頻率「唱」出來）。用 Julius O. Smith 的 CryBaby 數位近似：中心頻率 fr＝450·2^(2.3·w)（w＝踏板位置 0～1，450 Hz → 2216 Hz），Q＝2^(2(1−w)+1)（腳跟 8 → 腳尖 2）。Smith 的版本是兩極共振器加一個 DC 零點；這裡用 Web Audio 的帶通 biquad（同樣的極點，DC 和 Nyquist 各一個零點，吉他頻段裡的兩側斜率一樣），理由：它的峰值增益在任何 Q 都剛好是 0 dB，所以音量補償可以獨立而且準確地做（Smith 用 0.1·4^w 的增益是配他自己的共振器），而且在瀏覽器裡就是一個原生節點。100% 濕聲（真的 CryBaby 也沒有乾聲）。

**踏板位置怎麼動，不會有拉鍊聲：**每個聲部有一個位置訊號（`ConstantSourceNode`），雙軌的兩條鏈、可切換的兩份鏈裡的四個帶通都讀它：位置 → 一個增益（每單位 w 幾 cents）→ 帶通的 `detune`（頻率本身是低點，`detune` 做指數對應）；位置 → 固定曲線 4^(1−w)（`WaveShaperNode`）→ 乘上 Q 倍數 → 帶通的 `Q`；位置 → 斜率增益 → 固定指數曲線 → 偏移增益 → 補償的 `GainNode.gain`。所以移動踏板只是一個 AudioParam 的 `setTargetAtTime`，鏈裡其他東西都不動、不重建；旋鈕（範圍、共鳴…）是一般的段數字，照 15.1.3 的方式滑過去，開關娃娃音照樣用兩份鏈交叉淡化。Chrome 在參數有連線輸入時每個取樣重算濾波器係數；只在每 128 取樣更新一次的瀏覽器也有上限（下面的測試）。

**滑鼠滾輪（擁有者 2026-11-25：滑鼠只有一個游標，刷完弦來不及移到直條）：**`src/core/pedals/wheel.js`（純函式）＋`pedalboard.js` 的滾輪處理。

#### 15.1.5 延音（已實作，2026-11-25）

擁有者用滑鼠玩娃娃音時，和弦太快就沒聲音了，來不及「哇」。清音掉 10 dB 只要約 0.64 秒（搖滾＝丁約 2.5 秒、重金屬約 4 秒）。所以加一顆「延音」旋鈕，讓和弦（包括清音）響久一點。程式：`src/core/audio/karplus.js`（`SUSTAINER`）、`voice-params.js`、`electric-rig.js`（`rig.sustain`）、`src/core/pedals/model.js`（`AMP_TYPE`、`MACROS.sustain`）。

**做法：每條弦自己的延音器（壓縮器＋補償增益）。**在撥弦的 buffer 算出來的時候，就對那條弦自己的聲音做：包絡跟著弦的峰值走（每 32 個取樣更新一次：起音 2 ms、釋放 80 ms），包絡比門檻（−6 dB，相對於這條弦的峰值）低多少，就把它拉回來一部分：增益＝(1 − 1/比例)·(門檻 − 包絡) dB，最多到補償上限；增益在每 32 個取樣之間線性滑動。所以撥弦的那一下（在門檻上面）完全不變，之後的衰減在 dB 上慢「比例」倍，直到補償用完，弦才照原本的速度衰減。旋鈕 s（0～1）：比例 1＋5s（最大 6:1），補償上限 30s dB；0＝關（不做任何事，跟原本的取樣完全一樣）。buffer 的長度也跟著補償上限拉長（×(1＋補償/54)，最大 ×1.56），不然還聽得到的尾巴會被切掉。

**為什麼不用別的做法：**

- **把效果鏈前面放一顆壓縮器（DynamicsCompressorNode）：**真的延音效果器就是這樣，但它看到的是**所有弦加起來**的聲音：換和弦、新的一刷時，舊的聲音被收掉（音量往下），壓縮器會把它**拉回來**，收音就失效、和弦糊在一起；而且它在 Node 的量測模型裡只能近似。放在每條弦、而且在聲部的收音增益**前面**，收音完全照舊（下面的數字），也不會有和弦之間互相拉扯的「抽吸」感（像每條弦各接一顆壓縮器的六角拾音器做法）。
- **只把弦的 t60（Karplus 的迴圈增益）加長：**清音的快速衰減主要是泛音掉得快加上高音弦本來就短，加長 t60 對前 1 秒幫助不大；要加到夠長，弦會變得不像弦（低音弦已經在 t60 的上限 6 秒）。而且 buffer 會長很多，算尾巴的時間和記憶體都更多。延音器只在需要的時候把音量拉回來，泛音照樣自然變暗，比較像真的壓縮器＋破音的長延音。

**放在哪裡（D-016 的「簡單模式每顆效果器最多兩顆旋鈕」）：**延音屬於「音箱」（一直開著、沒有開關），不佔任何一顆效果器的旋鈕，也不用多一顆圓盤（腳踏區和 `4`～`9` 鍵都不變）。簡單模式：調整畫面中間的第三顆大旋鈕，排在破音程度、明亮度旁邊，玩家調音色時就會看到；進階模式：效果鏈點「音箱」，中間是延音旋鈕。滑鼠拖、滾輪、捏住上下拖都能轉。它和娃娃音的踏板位置一樣算「演奏的偏好」：換預設組時保留，轉它也不會讓預設組變成「自訂」（不然玩家調好延音再點「清音」，延音就被清掉，很意外）。存在 `airJam.pedalboard.v1` 的 `amp.params.sustain`，舊的存檔沒有這一項，讀進來就是 0。預設 0：每個預設組的聲音和量測數字都和之前一樣（搖滾＝丁沒變；測試逐一比對效果鏈、撥弦參數和取樣）。進階模式沒有再加更細的旋鈕（比例、門檻）：一顆就能從「原本」轉到「很長」，多的旋鈕在還沒有人聽過之前只是多餘的選擇。

**改了馬上生效、不重建：**延音只影響之後撥的弦，效果鏈不動（引擎的 `applyPedals` 換掉 `p.tone`，鏈的數字一樣就不更新）；已經在響的音不會突然變大。

**量測**（`node tools/tone-lab/measure.mjs --set sustain`，Node 模型；一刷 4 條弦 A5、力道 0.6，掉 10／20 dB 的秒數）：

| 預設組 | 延音 0 | 0.25 | 0.5 | 0.75 | 1 |
|---|---|---|---|---|---|
| 清音 | 0.72／1.44 | 1.29／2.11 | 1.82／2.72 | 2.52／3.39 | 3.20／4.09 |
| 搖滾 | 2.53／3.44 | 3.17／4.11 | 3.87／4.83 | 4.54／5.51 | 5.27／6.20 |

- **收音（8 條弦、力道 1）：**換和弦 80 ms 後：清音 70／70 dB、搖滾 92／85、重金屬 93／87（延音 0／1，都 ≥ 40）。新的一刷 30 ms 時：清音 66／67、搖滾 50／45、重金屬 19／21 dB；50 ms 時都 ≥ 55 dB。有破音時，延音開到最大，新的一刷在個別情況下要多幾 ms 才收乾淨（測試裡搖滾 30 ms 從 50 降到 38 dB）：進削波器的聲音比較大、低頻比較多，音箱的低頻濾波器在聲部收掉之後多響幾 ms；把聲部的收音再加深 30 dB 也沒有改善（試過，拿掉了）。新的一刷本身會蓋過它；測試要求 50 ms 時 ≥ 40 dB。
- **配歌（s14／s21，16 秒，每小節刷一次 8 條弦、換小節換和弦）：**延音 0／1 的混音峰值都是 0.972（歌本身的峰值），限制器最多 2.1 dB；清音的吉他 RMS 從 −12～−14.5 dB 變成 −6.7～−7.4 dB（響得久，平均就大聲），搖滾、重金屬幾乎不變（本來就被破音壓平）。一直刷八分音符時，每一刷都會收掉上一刷，延音幾乎沒有作用，自動配平的表不用改。
- **主執行緒：**延音器要在撥弦當下的前 0.4 秒一起算。Node（假的 AudioContext）每刷 8 條弦：延音 0 約 1.2 ms，0.25～1 約 2.7～3.1 ms（中位數 2.4～2.7 ms，最慢 7 ms；Node 的數字有垃圾回收的雜訊）。Chrome（這台電腦，示範曲播放中，預覽窗在背景）：延音 0 平均 2.5～2.9 ms、最大 3.0～3.1 ms，最慢 4.4～4.9 ms：每刷多 0.3～0.5 ms，在 30 fps 一格 33 ms 裡沒問題。尾巴照舊在空檔裡每次最多 4 ms 算，延音最大時尾巴長 1.56 倍；被收掉的尾巴照舊不算。

#### 15.1.6 後段效果匯流排（合聲、延遲、空間的接口；骨架已實作，效果還沒有聲音，2026-11-25）

合聲、延遲、空間是「跟時間有關」的效果，要放在**整個聲部**後面，不能放在每一軌（主軌＋雙軌）或每一份可切換的效果鏈裡，不然回音和殘響會變成好幾份。所以每個引擎聲部（`rhythm`、實驗室的每個組合，之後的 `lead`）有一條自己的後段匯流排，順序固定：

兩軌的效果鏈 → 左右聲像 → `trim` → **合聲 → 延遲 → 空間** → stringGain（→ glue → 限制器）

程式：`src/core/audio/post-fx/index.js`（順序、接線、Node 模型），每個效果一個檔案 `chorus.js`、`delay.js`、`reverb.js`。現在三個檔案都是**完全透明的直通**（輸入直接接到輸出，中間只有增益 1 的節點，沒有延遲、不改音量；Node 模型原封不動傳回），做效果的人只改自己的檔案（加上 `model.js` 的旋鈕、`availability.js` 和 `PEDALS_WITH_SOUND`、介面文字、測試、文件），不用改 `engine.js` 或 `app.js`。

**每個效果檔案要匯出的東西：**

| 名稱 | 什麼時候被呼叫 |
|---|---|
| `paramsFromSnapshot(snapshot)` | 純函式。效果器板的快照（`model.boardSnapshot()`，或 `null`）→ 這個效果的數字。沒有快照、踏板關著、或還沒有聲音（`sound: false`）都要回傳「關」 |
| `create(ctx, { input, output, part })` | 聲部第一次用到時建一次，之後換音色、轉旋鈕、開關都**不重建**。`input`、`output` 是匯流排的增益 1 節點（前一格的 output 就是下一格的 input），只在這兩個之間接自己的節點。剛建好時是關的 |
| `apply(params, change, { now, tau })` | 每次效果器板有變動（`applyPedals`），和這個聲部每次 `setTone`（`change.type === 'tone'`）。`tau`：轉旋鈕是旋鈕的平滑時間，其他（開關、預設組、載入、換音色）是開關的交叉淡化時間（引擎的 `PEDAL_TAU`） |
| `setTempo?(tempo, { now })` | `tempo = { pulseSeconds, beatSeconds }` 或 `null`（沒有歌）。建立聲部時（如果已經有歌）、載入歌、換音色或根音保護重建歌曲地圖、手動修正速度時；同樣的數字可能來兩次 |
| `onChordChange?(time)` | 遊戲換和弦（和收掉舊和弦的聲部同一刻，AudioContext 時間）。**每種音色都會叫**，木吉他不收音也一樣 |
| `onStrum?(time, velocity)` | 這個聲部開始新的一刷（和上一次撥弦相差超過 `strumWindow`）的第一條弦，時間是它開始發聲的時刻 |
| `dispose()` | 拆掉自己建的節點 |
| `process?(params, { left, right }, { sampleRate, tempo, chordChanges, strums })` | 選用：Node 模型（`tools/tone-lab/model.mjs` 的 `renderPart(..., { post, tempo })` 會用到），直通就原封不動傳回 |

**開關不能有爆音：**乾聲路徑 `input → output` 永遠接著、增益 1，不切換；效果是一條並聯的濕聲送進 `output`，開關只用 `setTargetAtTime(目標, now, tau)` 移動濕聲（或送進效果的量）。剛建好、關著的時候濕聲增益正好是 0，所以關著時輸出和輸入一模一樣。延遲和空間建議關掉「送進去」的量，讓已經在響的回音和殘響自然結束（效果器的 trails 模式）；關掉「出來」的量會把尾巴切掉。不要在演奏中重建節點：延遲線的最大長度、殘響的幾個固定大小的 IR 都在 `create` 時準備好。乾聲路徑不能加預看或延遲。

**哪些音色有：**每個聲部都有這條匯流排，但只有電吉他（`tone.rig`）聲部會拿到效果器板的設定；鋼弦、尼龍弦（本身已經有房間殘響）和實驗室的甲乙丙丁永遠拿到「關」，所以聲音完全不變。換到鋼弦時效果會照開關的方式淡出，換回電吉他再淡入。之後主奏聲部有自己的一條，和節奏分開。

**還沒做：**進階模式的效果鏈順序還是不影響聲音（後段順序固定）。測試：`node tests/post-fx.test.mjs`（順序、直通完全一樣（假的 AudioContext 和 Node 模型）、設定傳得到而且不重建、`setTempo`／`onChordChange`／`onStrum` 的值和時機）。

#### 15.1.7 合聲（已實作，2026-11-25）

後段匯流排的第一格（15.1.6），程式在 `src/core/audio/post-fx/chorus.js`。照類比合聲（BBD，研究文件裡的 CE-2 類）做：一條被三角波 LFO 來回推動的短延遲，和原本的聲音混在一起；延遲的那一份音高微微上下飄，和原本的聲音疊起來就是「晃動、變厚」的感覺。

**接法（建好一次，之後不重建）：**輸入 → 乾聲（增益 1）→ 輸出；另外輸入 → 合成單聲道 → 高通 150 Hz → 低通（音色）→ 兩條延遲線 → 左右聲像 → 濕聲增益 → 輸出。同一個 LFO 用 +深度 和 −深度 推兩條延遲線（相位差 180°），兩份分別擺在左右（寬度），所以晃動會在左右之間流動。

| 數字 | 值 | 理由 |
|---|---|---|
| 延遲中心 | 11 ms，± 深度 0～4 ms（7～15 ms） | 合聲的典型範圍：短於約 5 ms 會變成 flanger（噴射機聲），長於約 20 ms 會聽成另一把吉他的回音 |
| 速度 | 0.1～5 Hz（對數），預設 0.8 Hz | 慢的像水波、快的像顫抖；研究文件原本 0.1～3 Hz，放寬到 5 Hz 讓「快速顫抖」也做得出來 |
| 深度 | 0～4 ms，預設 ±2 ms | 預設在 0.8 Hz 時約偏 11 cents（像兩把吉他沒有完全調準）；三角波的偏移量 = 4 × 速度 × 深度，限制在 3%（約 50 cents）以內：速度很快時深度自動收小（5 Hz 時最多 ±1.5 ms），哪個角落都不會晃到走音 |
| 混合 | 0～50%，預設 40%（濕聲增益 0.67） | 50% = 濕聲和乾聲一樣大，是 CE-2 固定的混合；乾聲永遠是 1 |
| 音色（濕聲低通） | 1.5～8 kHz（對數），預設 4 kHz | BBD 前後一定有低通，所以類比合聲的濕聲偏暗、偏溫暖 |
| 高通（固定） | 150 Hz | 低音不晃、維持在中間、不吃動態空間 |
| 寬度 | 0～100%，預設 100% | 兩份濕聲的聲像 ∓寬度（Web Audio 的等功率聲像）；0 = 兩份疊在中間 |
| 音量（只在進階） | −12～+6 dB，預設 0 dB | 效果器的輸出音量：開著時乘在乾聲和濕聲上，關掉時回到正好 1 |

**簡單模式兩顆：速度、深度**（就是 CE-2 的兩顆旋鈕；不會樂器的人也聽得懂「晃多快、晃多少」），混合、音色、寬度用預設，音量固定 0 dB（乾聲完全不動）。進階模式六顆：速度、深度、混合、音色、寬度、音量。預設組都不開合聲（預設組沒有改）。

**開關和轉旋鈕：**照 15.1.6 的規則，只用 `setTargetAtTime` 移動濕聲（開關用引擎的開關 τ，旋鈕用旋鈕 τ），乾聲路徑沒有延遲；只有目標真的改變的參數才重新排程（娃娃音直條移動時 `applyPedals` 每格都會來，合聲不會被打擾）。關掉後 12 τ 把濕聲設成正好 0、乾聲正好 1，所以關著時輸出和輸入一模一樣。速度用 LFO 的頻率滑過去（相位連續），深度、寬度、音色也都是滑的，沒有一格一格的跳。

**Node 模型：**`renderChorus`（含參數自動化：每個參數照 `setTargetAtTime` 逐取樣平滑、低通每 128 個取樣更新、延遲線線性內插、等功率聲像）和 `process`（設定好的穩態；關著時原封不動傳回）。

**量測（Node，`node tests/chorus.test.mjs`；本機加 `AIRJAM_SAMPLES=<samples 資料夾>` 會再用 s14、s21）：**預設值打開合聲，聲部大聲約 +1.0 dB（清音和搖滾、示範曲和兩首範例歌都一樣），聲部峰值 ×1.11～1.26，總輸出峰值 0.97 不變（上限曲線），限制器多壓 0～0.2 dB；所有旋鈕轉到最大，總輸出峰值也 ≤ 1。濕聲對輸入：60 Hz −19.6 dB、1 kHz −3.6 dB、8 kHz −17.8 dB（音色轉到最大 −7.3 dB）；寬度 100% 時左右濕聲的相關係數約 0。開、轉到最極端、關的過程，取樣之間最大的跳動和穩態一樣（沒有爆音）；旋鈕從 0 跳到 1 時，每 128 個取樣最多走全程的 9.6%（τ 25 ms）。瀏覽器（滑鼠模式＋示範曲＋電吉他，用腳踏區的開關和拖旋鈕）：開關、旋鈕都接到節點，沒有 console 錯誤，連續刷六弦時匯流排輸出峰值約 0.70～0.80（輸入 0.59～0.66），限制器約 −1.4～−2.2 dB。**沒有人聽過。**

### 15.2 遊戲模式（玩家扮演的角色）

1. **伴奏手（第一版）：** 刷和弦、分解和弦。往下刷低音先響，往上刷高音先響。可加「節奏提示」：畫面亮出該撥哪條弦。
2. **獨奏手：**（**狀態：等使用者決定**，見 15.2.1 開頭）吸附改成五聲音階，加上**捏弦改變音高**（見 15.2.1）、電吉他破音＋手控娃娃音；在歌曲間奏提示「該你 solo 了！」。
3. **自彈自唱：** 卡拉 OK 式畫面，歌詞上方標和弦；歌詞用使用者提供的 LRC 檔；可用「中央聲道消除」減弱原唱。
4. **指彈一人樂團：** 左手撥長弦（低音）、右手撥短弦（旋律），進階關卡。
5. **合奏：** 兩人同時站在鏡頭前（`numHands: 4`），一人伴奏一人 solo；或之後用多台裝置連線。
6. **氛圍創作：** 不放歌，選調性與速度，自己拉一整片弦，長延遲＋殘響，可錄下來。

#### 15.2.1 捏弦改變音高（獨奏模式）

> **狀態：挑戰中，等使用者決定**（2026-11-25）。兩份設計挑戰都建議**不要**照這一節做主要玩法：[獨奏模式_設計挑戰.md](獨奏模式_設計挑戰.md) 建議改用遊戲擺好的「獨奏弦」，[搖滾獨奏_設計挑戰.md](搖滾獨奏_設計挑戰.md) 在那之上加了「追手」的速彈和搖滾音階規則。**在擁有者決定之前不要照這一節實作。**開頭「伴奏模式維持一條弦一個音」已經決定（[D-008](決定紀錄.md)）。

**為什麼要做：**目前一條弦在同一個和弦裡只發一個音（像豎琴或自動和弦琴），新手很好上手，刷弦就是和弦。但這樣很難彈旋律，也做不出滑音、推弦這些吉他最有表情的技巧，撥弦時另一隻手也閒著。真吉他是左手按琴格縮短振動長度來改變音高；獨奏模式用「捏」來模擬按琴格，物理規則和現有的「越短越高」完全一致。

**伴奏模式（預設）維持一條弦一個音不變**，這是新手最核心的體驗。捏弦只在獨奏模式開啟，對應真吉他「先學刷和弦、再學獨奏」的學習路線。

**玩法：**

| 動作 | 效果 | 對應的吉他技巧 |
|---|---|---|
| 一隻手**捏住弦上的某一點** | 弦被分成兩段，振動的是「捏點到較遠端點」那一段（或固定取靠撥弦手那一段，實作時選一種並保持一致）；這段越短音越高 | 左手按琴格 |
| 另一隻手撥弦（撥在振動的那一段上） | 發出捏點決定的音 | 右手撥弦 |
| 捏著的手**沿著弦滑動** | 音高連續滑到新的音，正在響的音跟著滑（不重新撥） | 滑音（slide） |
| 捏著的手**往弦的垂直方向推** | 音高往上彎，最多約一個全音，放回來音高回落 | 推弦（bend） |
| 捏住後不撥、直接把捏點快速移到另一格 | 用很小的音量發出新音 | 搥弦／勾弦（hammer-on／pull-off），之後再做 |
| 放開捏 | 回到整條弦的音 | 放開琴格（空弦） |

**規則：**

- **捏在弦上＝按弦，捏在空白處＝拉新弦。**判斷方式：捏住的瞬間，捏點離某條弦的距離小於門檻（例如 0.4 個手掌大小），就算按住那條弦；否則照舊開始拉新弦。兩手都捏在空白處才是拉弦。
- 用「捏」不用「按」：筆電鏡頭幾乎看不出手指的前後距離，分不出「靠近弦」和「按住弦」；捏的判斷已經有遲滯、很穩定。
- **吸附照常運作：**振動長度換成格子、吸附到五聲音階（或目前模式的音），所以捏在哪裡都不會出現錯音。弦上的刻度就是琴格，捏住時最近的刻度要亮起來。
- 滑音時，音高在格子之間**連續**移動（不吸附），停下來超過約 80 ms 才吸附到最近的格子，聽起來才像真的滑音。
- 捏住的弦要畫出捏點，振動的那一段亮、被捏掉的那一段暗。
- 一隻手同時只能按一條弦。按弦的手不能撥弦（沿用「捏住的手不能撥」的規則）。

**聲音實作：**Karplus-Strong 的音高由延遲線長度決定，滑音與推弦需要在聲音響著時改變音高。可行做法：預先算好的撥弦 buffer 用 `AudioBufferSourceNode.playbackRate` 即時調整（簡單，音色會跟著微微變），或改用 AudioWorklet 即時合成、直接改延遲線長度（較真實，工作量較大）。先用 `playbackRate`。

**計分：**獨奏模式不只看拍點，也可以加「旋律感」的獎勵，例如連續撥出由低往高或由高往低的音、在換和弦時落在和弦根音上。細節之後再設計。

**風險與要驗證的事：**

- 兩手協調的難度：需要真人測試，看新手多久能上手；可能需要「只能捏、自動撥」之類的輔助設定。
- 捏住弦時手會遮住弦，捏點的判斷要用捏住瞬間的位置，之後跟著手移動，不要每格重新找最近的弦。
- 捏點在弦端點附近時振動長度很短，音會很高，要限制可捏的範圍（例如弦長的 15%～85%）。

## 16. 之後的其他空中樂器

每個都用第 0 節的共用模組（聽歌、和弦吸附、節奏判定、特效）：

- **空中鼓：** 在空中拍出鼓面，手往下揮擊打；速度決定力度；依歌曲拍點判定。
- **空中琴：** 一排浮在空中的琴鍵，鍵永遠只對應目前和弦或音階的音（Feel Sync 式）。
- **空中特雷門琴：** 手的高低控制音高（吸附音階）、另一手控制音量，連續滑音。
- **空中貝斯：** 跟著和弦根音，簡單的低音線，適合合奏模式裡的第二位玩家。
