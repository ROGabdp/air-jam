# Air Jam（空中即興）：設計說明

> **Air Jam** 是一個給大家玩的手勢音樂遊戲：讓不會演奏樂器的人，也能跟著自己喜歡的歌享受即興演出的快樂。遊戲會聽歌、找出現在的和弦，玩家怎麼彈都和諧。
>
> Air Jam 會有多種「空中樂器」。**第一個樂器是「空中弦」**（這份文件第 3～11 節）：用雙手在空中拉出會留下來的弦，用手指撥弦。之後會加入其他樂器（見第 16 節）。
>
> 定位：先做成給一般玩家的完整遊戲，品質以真正玩家的體驗為準；之後再從完整專案拆出簡化版本給學生學習。

## 0. 架構：讓之後能加樂器

- 「聽懂歌曲」（解碼、拍點、和弦、調性）、「手部追蹤與手勢」、「和弦吸附」、「節奏判定與計分」、「畫面特效」做成**共用模組**，不綁在某一個樂器上。
- 每個樂器是一個獨立模組，提供一致的介面，例如：`init(ctx)`、`onHands(hands, time)`（收到手部資料）、`update(dt)`、`draw(ctx2d)`、`onChordChange(chord)`、`dispose()`。樂器透過共用的音高吸附、發聲與計分服務工作。
- 音色（木吉他、電吉他……）和樂器（空中弦、空中鼓……）分開：同一個樂器可以換音色。
- 程式可讀、模組清楚即可，不需要寫給初學者看的註解；註解用繁體中文或英文都可以，保持一致。

## 1. 目標與靈感

- **目標玩家：** 不會演奏任何樂器、但喜歡音樂的一般人。也要讓會樂器的人覺得好玩（`free` 模式、獨奏模式）。
- **核心體驗：** 放一首自己喜歡的歌 → 在空中拉幾條弦 → 跟著節奏撥 → 聽起來就像自己在幫這首歌伴奏。
- **靈感來源（要標註）：**
  - 一支 Facebook Reel：雙手捏出停在空中的弦，弦的長度決定音高，靈感來自 Pat Metheny 的 42 弦「畢卡索吉他」。
  - Casio CT-FS1 電子琴的 Feel Sync：分析歌曲的和弦進行，即時修正玩家彈的音高，讓人「彈不出錯音」。
- **我們自己加的部分：** 把 Feel Sync 的「和弦吸附」套在空中弦上、撥弦速度控制音量、撥弦位置控制音色、節奏判定與連擊。

## 2. 技術限制

- **純前端**，不加後端；音樂檔只在玩家自己的瀏覽器裡分析，**不上傳**。
- 手部追蹤：MediaPipe Tasks Vision `@mediapipe/tasks-vision@0.10.14`，從 jsDelivr CDN 載入，`numHands: 2`，`runningMode: 'VIDEO'`。
- 聲音：瀏覽器內建 **Web Audio API**，不用其他函式庫。
- 原生 ES module、不需要建置步驟，用本機伺服器開啟（`python -m http.server`），之後發布到 GitHub Pages 之類的靜態網站。檔案結構依第 0 節的模組劃分（例如 `src/core/`、`src/instruments/`），自行決定。
- 把可調整的數值集中在設定物件（`SETTINGS`），之後可以接到遊戲內的設定選單。
- 畫面像照鏡子（影片左右翻轉），**手的座標也要用同一個翻轉**，弦、手、撥弦判定都在同一個座標系統裡。
- 介面文字先用繁體中文，但集中管理，之後方便加英文。
- 以 Chrome／Edge 桌機為主要目標；Safari、手機之後再支援，不要寫死只能在 Chrome 跑的東西。

## 3. 遊戲流程

1. **開始畫面：** 標題、一句說明、兩個按鈕：
   - 「選一首我的歌」（`<input type="file" accept="audio/*">`，MP3／WAV／M4A）
   - 「用內建示範曲」（程式自己合成的伴奏，見第 7 節）
   - 這一下點擊同時解鎖瀏覽器的聲音（瀏覽器規定要使用者先點一下才能出聲）並打開鏡頭。「選一首我的歌」要在**打開檔案視窗之前**就解鎖聲音：選檔案可能花很久，等到選好時那一下點擊已經「過期」了。之後每次按「開始演奏」「再玩一次」也會再呼叫一次 `resume()`。
   - 超過 `maxSongMinutes`（預設 15 分鐘）的檔案不分析，請玩家換一首（解碼後的音訊每分鐘約 23 MB）。
2. **分析歌曲：** 顯示「正在聽這首歌…」與進度條。把整首歌先分析一遍，得到 **拍點時間表** 和 **每一段的和弦**（見第 6 節）。
3. **暖身（實作時加的）：** 分析完先進入「先拉幾條弦試試看」，歌還沒開始，可以拉弦、撥弦聽聲音（不計分）。按「開始演奏」或空白鍵才開始播歌。這樣玩家不用一邊聽歌一邊摸索怎麼拉弦。
4. **遊戲中：**
   - 背景是鏡頭畫面（稍微調暗），上面畫手、弦、粒子。
   - 畫面上方顯示：歌曲進度條、**現在的和弦名稱**（例如 `Am`）、下一個和弦的預告、分數與連擊數。
   - 歌曲播放，玩家拉弦、撥弦。
5. **結束畫面：** 歌曲播完（或按 `Esc` 提早結束）後顯示分數、最高連擊、Perfect／Good 次數，按鈕「再玩一次」「換一首歌」。

## 4. 手勢

用 MediaPipe 的 21 個點。距離一律**除以手掌大小**（第 0 點手腕到第 9 點中指根部的距離），手離鏡頭遠近才不會影響判斷。

### 4.1 捏住（拉弦用）

- 拇指尖（4）與食指尖（8）的距離 / 手掌大小 < `pinchOn`（例如 0.35）→ 捏住。
- 要大於 `pinchOff`（例如 0.5）才算放開。兩個門檻不同（遲滯），避免手抖造成一直閃爍。
- 捏點位置 = 4 與 8 的中點。

### 4.2 拉出一條弦

1. 兩手**都**捏住 → 開始拉弦，兩個捏點之間畫出「預覽弦」（半透明、虛線），弦上畫刻度。
2. 拉的時候即時顯示這條弦**現在會發什麼音**（例如在弦旁邊寫 `Do`／音名），刻度畫在可以吸附的長度上，像吉他的琴格。
3. 兩手放開（任一手先放開也可以，給 150 ms 寬限）→ 弦固定在空中，變成實線，輕輕「叮」一聲當作確認。
4. 太短的弦（< 畫面寬度的 8%）不建立。
5. 弦數上限 `maxStrings`（預設 8）。超過時最舊的那條淡出消失。

### 4.3 撥弦

- 用**食指尖（8）**撥。正在捏（拉弦中）的手**不能**撥弦，避免拉新弦時誤撥舊弦。
- 判定方式：每一格記住指尖在每條弦的哪一側（外積的正負號）。上一格與這一格的**側邊改變**，而且指尖的移動線段真的和弦線段相交 → 撥到了。這比判斷「碰到」穩定，手抖也不會一直觸發。
- 同一條弦撥完後有冷卻 `pluckCooldown`（例如 120 ms）。
- **一次劃過好幾條弦＝刷和弦**：一格內撥到的多條弦，依照手指經過的順序間隔約 15 ms 依序發聲，聽起來像刷吉他。
- 撥弦時讀出兩個資訊：
  - **手指速度**（像素／秒，除以手掌大小）→ 音量。慢慢撥小聲，用力刷大聲。
  - **撥的位置**（在弦上的比例 0～1，中間是 0.5）→ 音色。靠近端點比較亮、比較尖；撥中間比較圓潤（真吉他也是這樣）。

### 4.4 其他手勢

- **刪除一條弦：** 單手握拳，拳頭中心停在某條弦上 0.8 秒 → 那條弦碎成粒子消失。
- **全部清空：** 雙手同時握拳 1 秒。
- （之後可以加）張開手掌往上推 → 調整音量。

握拳判定：四根手指的指尖（8、12、16、20）到手腕（0）的平均距離 / 手掌大小 < 門檻。

## 5. 音高：讓人彈不出錯音（核心）

### 5.1 長度決定「這條弦在第幾格」

真的弦越長越低，這裡保留這個直覺，但不直接把長度換成頻率，而是換成「格子」：

- 把弦長正規化：`t = (長度 - 最短) / (最長 - 最短)`，最短、最長約為畫面寬度的 8% 和 90%。
- 長的弦 → 低音，短的弦 → 高音。分成 `slots` 格（預設 10 格，橫跨大約兩個八度）。
- 每一格代表「**目前和弦的第 N 個和弦內音**」，由低往高排。例如和弦是 C（C E G），格子依序是 C3 E3 G3 C4 E4 G4 C5 …

### 5.2 和弦一換，弦就自動「重新調音」

- 每條弦存的是「第幾格」，不是固定的頻率。
- 歌曲換到 `Am`，同一條弦會自動變成 Am 的和弦內音（A C E）的對應位置。
- 這就是 Feel Sync 的做法：**按哪裡都對**，因為整組弦永遠只會發出現在這個和弦裡的音。
- 換和弦時，所有弦的顏色在 0.3 秒內漸變成新和弦的顏色，讓玩家「看到」和弦換了。
- 正在響的音不要突然換高，下一次撥才用新音高。

### 5.3 三種吸附模式（設定裡可以切換）

| 模式 | 說明 | 適合 |
|---|---|---|
| `chord`（預設） | 只會發出目前和弦的和弦內音 | 完全不會的人，怎麼撥都和諧 |
| `scale` | 吸附到歌曲調性的音階（大調或小調的 7 個音） | 想彈一點旋律的人 |
| `free` | 不吸附，長度直接換成頻率（頻率 ∝ 1／長度） | 想自己玩、會一點音樂的人 |

沒有分析結果時（例如分析失敗），自動退回 `scale` 模式並用 C 大調五聲音階（C D E G A），一樣不會有難聽的音。

## 6. 聽懂一首歌（在瀏覽器裡分析）

歌曲載入後**先完整分析一次**再開始播放（比邊播邊分析穩定，也能預告下一個和弦）。分析可以放在 `setTimeout` 分段做或用 Web Worker，不要讓畫面卡住；進度條要會動。

**實作：** 分析寫成 generator（`analyzeSteps`），在主執行緒上每 20 ms 切一段（`analyzeAsync`），Node 測試用同一份程式一次跑完（`analyzeSync`）。沒有用 Web Worker：一首 4 分鐘的歌約 2～3 秒，分段已經夠順；之後如果要支援手機再考慮。

### 6.1 解碼

`AudioContext.decodeAudioData` → 混成單聲道 → 降取樣到約 11025 Hz（夠分析和弦，也比較快）。

### 6.2 拍點（節奏）

1. 每一小段（例如 hop 512 樣本）算頻譜，計算**頻譜流量**（spectral flux：這一段比上一段「變大」的能量總和），得到「起音強度」曲線。
2. 對起音曲線做自相關，在 70～180 BPM 範圍內找最強的週期 → BPM。
3. 用動態規劃或簡單的「找最符合的起點相位」，排出整首歌的拍點時間表。
4. 每 4 拍當作一小節（第一拍畫得比較明顯）。

### 6.3 和弦

1. 用 FFT（自己寫一個小的 radix-2 FFT 就好，不用函式庫）算每一段的頻譜，把 55 Hz～2000 Hz 的能量依音名（C、C#、…、B）加總成 **12 維的色度向量（chroma）**，再正規化。
2. 以**每一拍**為單位，把那一拍內的 chroma 平均。
3. 和 **24 個和弦模板**（12 個大三和弦＋12 個小三和弦，例如 C = C、E、G 三個位置為 1）做相似度比對，取最高分。
4. 平滑化：和弦通常至少持續 2 拍。用簡單的方法（例如 Viterbi，換和弦有懲罰；或「連續兩拍都一樣才換」）去掉亂跳。
5. 用整首歌的 chroma 總和，和大調／小調輪廓（Krumhansl 調性輪廓）比對，估出**調性**，給 `scale` 模式用。

**實作補充：**

- 色度只取頻譜峰值（拋物線內插）。一個很大聲的單音（人聲、主旋律）的第 3、第 5 泛音剛好是它的五度和大三度，會讓單音看起來像大三和弦，所以當一個峰值的 1/3 或 1/5 頻率上有一樣大或更大的峰值時，它的權重打三折（`overtoneSuppression`）。
- 小節的第一拍：找「和弦變化最大」的相位。Viterbi 換和弦的懲罰在第一拍最小、第 2、4 拍最大。
- 拍點：頻譜流量 → 自相關找週期（偏好 110 BPM 左右）→ 用低音頻帶的起音曲線決定要不要改成兩倍速度 → Ellis 動態規劃排拍點 → 區域線性回歸去掉量化抖動。前後安靜的地方用相同間隔補上拍點。

**準確度（`node tests/analysis.test.mjs`）：**

| 測試歌 | BPM | 每拍和弦正確率 |
|---|---|---|
| 8 首簡單合成伴奏（三和弦、各種速度、有無鼓、旋律、雜訊） | 全對 | 91～100% |
| 撥弦吉他樂團：三和弦、搖擺、速度 96→101、前奏只有鼓、小聲人聲 | 對 | 94% |
| 同上，但是七和弦＋轉位 | 對 | 44% |
| 同上，人聲很大聲 | 對 | 16% |
| 慢歌 70 BPM：分解和弦、轉位和弦、沒有鼓、人聲很大聲 | 猜成兩倍（138） | 39% |

結論：拍點在所有測試裡平均誤差都在 7 ms 以內；和弦在「伴奏清楚的三和弦流行歌」上可靠，**七和弦和大聲的人聲是主要弱點**。之後可以試的方向：用立體聲的左右差（人聲通常在正中間）、NNLS 色度、加入七和弦模板再對應回三和弦。這些都要用真的歌測過再決定。

分析的準確度不需要完美：就算和弦猜錯，`chord` 模式發出的仍然是三和弦的音，頂多「有點怪」，不會刺耳。**在結束畫面或說明裡誠實寫出：「和弦是程式猜的，不一定每個都對。」**

### 6.4 播放

用 `AudioBufferSourceNode` 播放解碼好的歌，以 `audioContext.currentTime` 為準來對照拍點與和弦時間表（不要用 `Date.now()`，才會跟聲音同步）。音量設定：歌曲 `songVolume`、撥弦 `stringVolume`，分開可調。

## 7. 內建示範曲

讓沒有音樂檔、或想先測試的人也能玩，而且**拿來驗證分析程式對不對**：

- 程式自己合成一段約 40 秒的伴奏：100 BPM，和弦進行 `C – G – Am – F` 重複，每個和弦 1 小節（4 拍）。
- 樂器：低音（和弦根音）、鋪底和弦（柔和的三角波）、簡單的鼓（大鼓在 1、3 拍，小鼓用雜訊在 2、4 拍）。
- **實作：** 改用純 JavaScript 合成（`src/core/song/backing-synth.js`），不用 `OfflineAudioContext`，這樣 Node 測試和瀏覽器分析的是同一個訊號。
- 合成出來的聲音 **走跟玩家音樂檔一模一樣的分析流程**，不要偷用已知答案。分析結果應該要接近 100 BPM 和 `C G Am F`；開發者可以在 console 印出比對結果。

## 8. 撥弦的聲音

使用 **Karplus-Strong 撥弦合成**：一小段隨機雜訊，放進「延遲線＋低通平均」的迴圈裡，會自然變成很像吉他的撥弦聲。

- 每次撥弦預先算好一個短的 `AudioBuffer`（約 2 秒）再播放，最簡單也最穩定（不用 AudioWorklet）。
- 頻率決定延遲線長度；`decay` 決定餘音長短。**實作：** 餘音用「衰減 60 dB 的秒數」計算，音越高餘音越短（像真的弦）；`decay` 當作整體倍率，0.996 是標準長度，越接近 1 越長。延遲線加一個全通濾波器補小數部分，音準誤差在 1 cent 以內。
- 同一條弦再撥一次時，上一個還在響的聲音會很快淡出（像真的弦被手指碰到），不會疊在一起。
- **撥的位置** → 初始雜訊先做一點低通（撥中間＝低通多一點，聲音圓潤；撥端點＝幾乎不過濾，聲音亮）。
- **速度** → 音量（GainNode），設上下限。
- 加一點點立體聲左右（StereoPanner）：弦的中點在畫面左邊就偏左聲道。
- 同時發聲的數量上限（`maxVoices`，16 個），太多就把最舊的淡出，避免爆音。撥弦先經過一個輕的壓縮器，再和歌曲一起進最後的限制器（`DynamicsCompressorNode`）防止破音。

## 9. 遊戲性：節奏判定

不會彈的人也需要「我有沒有彈好」的回饋，但**不能有懲罰感**。

- 撥弦時間和最近的拍點比較：
  - 差距 ≤ 70 ms → **Perfect**（大的金色字＋較多粒子）
  - 差距 ≤ 150 ms → **Good**
  - 其他 → 照樣發聲、照樣好聽，只是不加分（不顯示 Miss，不扣分）
- 連續 Perfect／Good → 連擊數增加，連擊越高，弦的光暈越亮、粒子越多。
- **實作：** 不在拍子上的撥弦**不會**中斷連擊（不然隨意撥弦會有懲罰感）；連續 `comboIdleBeats`（8）拍都沒有得分，連擊才悄悄歸零。每一拍只算一次分，在同一拍附近亂撥不會一直加分。
- **延遲補償：** 判定時間 = 歌曲時間 − 喇叭輸出延遲（`outputLatency`）− 輸入延遲（鏡頭 `cameraLatency` 60 ms、滑鼠 `mouseLatency` 12 ms），以玩家「聽到」的拍子為準。
- 顯示和吸附用的和弦比聽到的聲音早 `chordLookahead`（40 ms）切換，剛好在換和弦那一拍撥下去，也會發出新和弦的音。
- 在**小節第一拍**撥到，而且那一拍剛好換和弦 → 額外加分（「跟上換和弦了！」）。
- 畫面邊緣有隨拍點閃動的提示光（第一拍比較亮），讓玩家看得到節奏。
- 刷和弦（一次撥到 3 條以上）且在拍點上 → 分數加倍。`strumWindow`（140 ms）內的撥弦算同一次刷弦，只判定一次。

## 10. 視覺

- **弦：** 發光的線（畫兩次：粗而半透明的光暈＋細而亮的芯）。顏色依目前和弦決定（12 個根音對應色相環的 12 個顏色，小和弦稍微暗一點）。
- **刻度：** 弦上畫小刻度，表示吸附的格子；拉弦時更明顯，固定後變淡。
- **震動：** 撥弦後，弦畫成會衰減的駐波：在撥的位置彎最多，`振幅 × sin(…)`，振幅隨時間指數變小，和聲音的餘音同步。
- **粒子：** 撥的位置噴出粒子，顏色跟弦一樣。Perfect 時更多。
- **手：** 畫 21 個點和連線，但淡一點；捏住時捏點畫成亮圈，食指尖畫成小光點，方便瞄準。
- 鏡頭畫面調暗約 40%，讓弦和粒子更明顯。

## 11. 沒有鏡頭也能測（滑鼠模式）

方便開發和在沒有鏡頭的電腦上展示，也讓自動測試做得到：

- 按 `M` 鍵切換滑鼠模式（或網址加 `?mouse=1`）。
- **拖曳**（按住滑鼠左鍵拉）＝拉一條弦，放開就固定。
- **不按鍵移動滑鼠穿過弦**＝撥弦（速度一樣換算音量）。
- 右鍵點弦＝刪除那條弦。
- 滑鼠模式下不需要鏡頭權限，畫面背景用深色漸層。
- 打不開鏡頭（拒絕權限、沒有鏡頭、不是 localhost／https）或手部追蹤模型下載失敗時，自動切換成滑鼠模式並提示玩家。

## 12. 設定（`SETTINGS`）

```js
const SETTINGS = {
  snapMode: 'chord',     // 'chord' 和弦內音／'scale' 音階／'free' 不吸附
  slots: 10,             // 弦長分成幾格（越多，音域越廣）
  lowestNote: 'C3',      // 最長的弦大約從哪個音開始
  maxStrings: 8,         // 最多幾條弦
  pinchOn: 0.35,         // 捏住的門檻（越小越要捏緊）
  pinchOff: 0.5,         // 放開的門檻
  pluckCooldown: 120,    // 同一條弦多久才能再撥一次（毫秒）
  songVolume: 0.8,       // 歌曲音量
  stringVolume: 0.9,     // 撥弦音量
  decay: 0.996,          // 撥弦餘音（越接近 1 越長）
  perfectWindow: 70,     // Perfect 判定範圍（毫秒）
  goodWindow: 150,       // Good 判定範圍（毫秒）
  showHand: true,        // 要不要畫出手的 21 個點
  videoDim: 0.4,         // 鏡頭畫面調暗多少

```

## 13. 會遇到的問題

| 問題 | 原因 | 解法 |
|---|---|---|
| 按了沒聲音 | 瀏覽器規定使用者要先點一下才能播放聲音 | 開始按鈕的那一下同時 `audioContext.resume()`；選檔案要在打開檔案視窗前就解鎖 |
| 切到滑鼠模式後鏡頭燈還亮著 | 鏡頭或模型還在載入時就切換了 | 載入完成時檢查是否已經切換，是的話關掉鏡頭 |
| 手指明明碰到弦卻撥不到 | 影片翻轉了，手的座標沒翻 | 所有座標用同一套翻轉 |
| 拉新弦時舊弦一直響 | 捏住的手也被當成在撥弦 | 捏住的手不能撥 |
| 捏住判斷一直閃 | 手會抖，一個門檻不夠 | 捏住和放開用兩個不同門檻 |
| 一次撥好幾聲 | 指尖在弦附近抖 | 用「穿過」判斷＋冷卻時間 |
| 聲音和畫面對不上 | 用了 `Date.now()` 計時 | 改用 `audioContext.currentTime` |
| 很多弦一起響會爆音 | 音量加總太大 | 同時發聲上限＋壓縮器 |
| 分析一首歌時畫面卡住 | 一次算完整首歌 | 分段計算或用 Web Worker，顯示進度 |
| 和弦有時候猜錯 | 自動分析本來就不完美（人聲、鼓聲會干擾） | 平滑化，並誠實告訴玩家 |

## 15. 之後可以加的：空中弦

- **共鳴弦**（畢卡索吉他的特色）：撥一條弦時，和它同音或差八度的其他弦也輕輕震動、微微發光。
- 錄下自己的演奏，和歌曲混在一起存成檔案。
- 發布到網站，手機與平板也能玩（觸控模式）。
- 新手教學關卡：一步一步教拉弦、撥弦、刷弦。

### 15.1 音色

同一個撥弦演算法（Karplus-Strong）加上不同的參數與效果鏈：

| 音色 | 做法 |
|---|---|
| 木吉他（鋼弦） | 預設；餘音長、明亮，加一點殘響 |
| 古典吉他（尼龍弦） | 較暗、較圓，起音柔和 |
| 電吉他乾淨音 | 中等亮度，加 chorus |
| **電吉他破音** | `WaveShaperNode` 削波 → **音箱模擬**（低通約 4–5 kHz＋EQ，或 `ConvolverNode` 套音箱脈衝響應；沒有這層會又刺又沙） |
| 烏克麗麗、豎琴 | 調整音域、餘音與亮度 |

效果器：Distortion／Overdrive、**娃娃音（Wah）**（帶通濾波移動中心頻率約 400 Hz ↔ 2 kHz）、Chorus／Flanger（調變短延遲）、Delay（延遲＋回授）、Reverb（卷積殘響）、推弦／搖桿（改變播放速率）。

兩個 Air Jam 才有的玩法：
- **用手控制娃娃音：** 沒在撥弦的那隻手的高度控制 Wah 濾波頻率，取代真吉他的腳踏板。
- **破音時改用強力和弦：** 三和弦加重破音會糊掉，所以破音音色下的「和弦吸附」自動改成只用根音＋五度。

### 15.2 遊戲模式（玩家扮演的角色）

1. **伴奏手（第一版）：** 刷和弦、分解和弦。往下刷低音先響，往上刷高音先響。可加「節奏提示」：畫面亮出該撥哪條弦。
2. **獨奏手：** 吸附改成五聲音階，加上**捏弦改變音高**（見 15.2.1）、電吉他破音＋手控娃娃音；在歌曲間奏提示「該你 solo 了！」。
3. **自彈自唱：** 卡拉 OK 式畫面，歌詞上方標和弦；歌詞用使用者提供的 LRC 檔；可用「中央聲道消除」減弱原唱。
4. **指彈一人樂團：** 左手撥長弦（低音）、右手撥短弦（旋律），進階關卡。
5. **合奏：** 兩人同時站在鏡頭前（`numHands: 4`），一人伴奏一人 solo；或之後用多台裝置連線。
6. **氛圍創作：** 不放歌，選調性與速度，自己拉一整片弦，長延遲＋殘響，可錄下來。

#### 15.2.1 捏弦改變音高（獨奏模式）

**為什麼要做：**目前一條弦在同一個和弦裡只發一個音（像豎琴或自動和弦琴），新手很好上手，刷弦就是和弦。但這樣很難彈旋律，也做不出滑音、推弦這些吉他最有表情的技巧，撥弦時另一隻手也閒著。真吉他是左手按琴格縮短振動長度來改變音高；獨奏模式用「捏」來模擬按琴格，物理規則和現有的「越短越高」完全一致。

**伴奏模式（預設）維持一條弦一個音不變**，這是新手最核心的體驗。捏弦只在獨奏模式開啟，對應真吉他「先學刷和弦、再學獨奏」的學習路線。

**玩法：**

| 動作 | 效果 | 對應的吉他技巧 |
|---|---|---|
| 一隻手**捏住弦上的某一點** | 弦被分成兩段，振動的是「捏點到較遠端點」那一段（或固定取靠撥弦手那一段，實作時選一種並保持一致）；這段越短音越高 | 左手按琴格 |
| 另一隻手撥弦（撥在振動的那一段上） | 發出捏點決定的音 | 右手撥弦 |
| 捏著的手**沿著弦滑動** | 音高連續滑到新的音，正在響的音跟著滑（不重新撥） | 滑音（slide） |
| 捏著的手**往弦的垂直方向推** | 音高往上彎，最多約一個全音，放回來音高回落 | 推弦（bend） |
| 捏住後不撥、直接把捏點快速移到另一格 | 用很小的音量發出新音 | 搥弦／勾弦（hammer-on／pull-off），之後再做 |
| 放開捏 | 回到整條弦的音 | 放開琴格（空弦） |

**規則：**

- **捏在弦上＝按弦，捏在空白處＝拉新弦。**判斷方式：捏住的瞬間，捏點離某條弦的距離小於門檻（例如 0.4 個手掌大小），就算按住那條弦；否則照舊開始拉新弦。兩手都捏在空白處才是拉弦。
- 用「捏」不用「按」：筆電鏡頭幾乎看不出手指的前後距離，分不出「靠近弦」和「按住弦」；捏的判斷已經有遲滯、很穩定。
- **吸附照常運作：**振動長度換成格子、吸附到五聲音階（或目前模式的音），所以捏在哪裡都不會出現錯音。弦上的刻度就是琴格，捏住時最近的刻度要亮起來。
- 滑音時，音高在格子之間**連續**移動（不吸附），停下來超過約 80 ms 才吸附到最近的格子，聽起來才像真的滑音。
- 捏住的弦要畫出捏點，振動的那一段亮、被捏掉的那一段暗。
- 一隻手同時只能按一條弦。按弦的手不能撥弦（沿用「捏住的手不能撥」的規則）。

**聲音實作：**Karplus-Strong 的音高由延遲線長度決定，滑音與推弦需要在聲音響著時改變音高。可行做法：預先算好的撥弦 buffer 用 `AudioBufferSourceNode.playbackRate` 即時調整（簡單，音色會跟著微微變），或改用 AudioWorklet 即時合成、直接改延遲線長度（較真實，工作量較大）。先用 `playbackRate`。

**計分：**獨奏模式不只看拍點，也可以加「旋律感」的獎勵，例如連續撥出由低往高或由高往低的音、在換和弦時落在和弦根音上。細節之後再設計。

**風險與要驗證的事：**

- 兩手協調的難度：需要真人測試，看新手多久能上手；可能需要「只能捏、自動撥」之類的輔助設定。
- 捏住弦時手會遮住弦，捏點的判斷要用捏住瞬間的位置，之後跟著手移動，不要每格重新找最近的弦。
- 捏點在弦端點附近時振動長度很短，音會很高，要限制可捏的範圍（例如弦長的 15%～85%）。

### 15.3 曲風節奏模式

同一首歌可以選不同曲風，改變判定規則與音色：

| 曲風 | 判定／玩法 | 音色 |
|---|---|---|
| 民謠／流行 | 正拍刷和弦 | 木吉他 |
| 搖滾 | 強力和弦，下撥為主 | 電吉他破音 |
| 雷鬼 | 只有反拍（2、4 拍）算 Perfect，短切音 | 電吉他乾淨音 |
| 放克 | 16 分音符，刷完握拳悶音 | 乾淨音，短促 |
| Bossa Nova | 拇指低音＋切分和弦 | 古典吉他 |
| 藍調 | 獨奏模式＋推弦，藍調音階 | 微破音 |

## 16. 之後的其他空中樂器

每個都用第 0 節的共用模組（聽歌、和弦吸附、節奏判定、特效）：

- **空中鼓：** 在空中拍出鼓面，手往下揮擊打；速度決定力度；依歌曲拍點判定。
- **空中琴：** 一排浮在空中的琴鍵，鍵永遠只對應目前和弦或音階的音（Feel Sync 式）。
- **空中特雷門琴：** 手的高低控制音高（吸附音階）、另一手控制音量，連續滑音。
- **空中貝斯：** 跟著和弦根音，簡單的低音線，適合合奏模式裡的第二位玩家。
